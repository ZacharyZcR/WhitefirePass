# 山灵架构：角色只管演，山灵主持

## 目标

现在每个 AI 既是角色又是玩家：同一份 prompt 里一半是"你是诺拉"，一半是规则、工具和 JSON 格式，演起来两头都不像。

新架构把两件事拆开：

- **角色 AI**：完全沉浸在角色里。不知道这是游戏，没有规则说明、没有工具、没有格式要求，只用人物的口吻说话、想事情。
- **山灵 AI**：契约的主人，也是唯一知道规则的 AI。在戏里向人发问、听懂他们的回答、宣布结果，把每个人该知道的事悄悄告诉他。
- **游戏引擎**（现有代码）：规则的唯一裁决者。算票、判断门闩是否挡住猎杀、谁死、谁赢。山灵只负责"听懂"和"讲述"，不判定。

## 三层分工

```
            ┌──────────── 引擎（规则裁决，状态唯一来源）────────────┐
            │  阶段推进 · 合法目标 · 算票 · 结算死亡 · 胜负            │
            └──────────────▲───────────────────────┬──────────────┘
                 行动（结构化）│                       │ 发生了什么
            ┌─────────────────┴───────────────────────▼──────────────┐
            │  山灵 AI：发问 · 解析回答 · 追问 · 讲述 · 私语          │
            └──────▲──────────────────────────────────────┬──────────┘
               戏里的回答│                                   │ 山灵的话（按可见性投递）
            ┌───────────┴──────────────────────────────────────▼─────┐
            │  15 个角色 AI，各自一个持续会话                          │
            └────────────────────────────────────────────────────────┘
```

## 角色会话

**开头（固定，整局不变）**：
- 人设原文：`game-engine.ts` 的 personalities，一字不改。
- 世界引入：你在哪、发生了什么。
- 身份用戏里的说法交给它，不是能力说明书。例如聆心者："山灵在你身上留了一道烙印。夜里，你能听见一个人灵魂的颜色。"

**之后按时间顺序追加**：
- 你听到的话：`诺拉·格雷说：「……」`
- 山灵对你说的话：公开宣告，或只对你的私语、发问。
- 你自己说过的话：作为 assistant 消息。

**角色的输出**：只有人物说出口的话，纯文本。心声见文末"待定"。

**会话不单独存储**：每个角色的会话，都由 `gameState.messages` 按可见性**现场重建**。
- 消息只追加、顺序固定，所以重建出的会话前缀每次都一样，DeepSeek 的前缀缓存照样命中，长会话也便宜。
- 存档不会因此膨胀，记录簿等现有界面直接复用。

## 山灵

山灵每次调用时能看到完整局面（上帝视角）和规则。它做四件事：

1. **发问**：用戏里的话问需要做决定的人。例如黄昏时问全员："献祭石握在你手里。你把它放在谁面前？"夜里只问聆心者："烙印在发烫。今夜你要去听谁的灵魂？"
   问句可以是写好的模板，加上山灵对局面的一两句点染，不必每次都单独调用一次。
2. **解析**：把一批戏里的回答一次读完，输出结构化行动，如 `{"诺拉·格雷": "马库斯·霍克", "托马斯·克劳利": null, …}`。
   这一步给出的目标仍由引擎校验是否合法。
3. **追问**：解析不出、或目标不合法时，在戏里追问一句："你是说……克劳利先生？"追问仍不行，就按弃权处理。
4. **讲述**：把引擎结算的结果写成山灵的话，再按可见性投递：
   - 公开：黎明的死讯、献祭的结果、随机事件。
   - 只给一个人：聆心者的倾听结果、食灰者尝到的灰、背誓者第二天的堕落。
   - 只给一群人：烙印者之间的低语。

## 一天怎么走

| 阶段 | 发生什么 | 调用 |
|---|---|---|
| 黎明 | 山灵宣告昨夜的结果（公开） | 山灵 ×1 |
| 白天 | 按顺序轮到谁，谁就在自己的会话里开口；说的话追加进其他人的会话 | 角色 ×N（串行，后面的人要听前面的话） |
| 黄昏 | 山灵向所有活人发问 → 全员**并行**作答 → 山灵一次解析 → 引擎算票 → 山灵讲述献祭 | 角色 ×N 并行，山灵 ×2 |
| 夜 | 聆心者、设闩者**并行**作答；烙印者在共享的低语里商量，再各自作答 → 山灵解析 → 引擎结算 → 山灵私语结果 | 角色若干，山灵 ×2 |
| 密会 | 两人轮流说话，各自的话只追加进对方的会话 | 角色 ×2 |

投票和夜间行动从串行改为并行，每天的等待时间会明显缩短。

## 可见性

沿用现有的 `visibility`（`all` / `marked` / `listener` / `guard` / `coroner` / `twins` / `{player}` / `{secretMeeting}`）。

一条消息进入哪些人的会话，完全由它决定。山灵的私语就是 `visibility: {player}` 的消息。

上帝视角开关、记录簿、语音字幕，都已经按这套可见性在工作，不用改。

## 代码上的变动

**删掉**：
- `ai/cli.ts`、`submit` 工具、怀疑名单。
- `ai/prompt.ts` 的大部分。

**新增**：
- `ai/session.ts`：从 messages 为某个角色重建会话。
- `ai/shanling.ts`：山灵的发问、解析、讲述。
- 角色和山灵的开场文本，单独放一个文件，交给 4.6 写。

**保留**：
- 引擎和 `actors.ts`：合法目标名单，现在给山灵用。
- store 的骨架。推进流程要改成"发问 → 并行作答 → 解析 → 结算 → 讲述"。
